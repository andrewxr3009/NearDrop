# Android architecture

`app` contains the application entry point, theme shell and intent routing. `core` defines app-level models and the native boundary. `design-system` owns visual primitives. `feature-home`, `feature-send`, `feature-receive`, `feature-devices` and `feature-settings` own their own Compose screen components. `data` owns repositories and test adapters.

The system Sharesheet dispatches `ACTION_SEND` and `ACTION_SEND_MULTIPLE` into the exported app activity. Incoming content is represented as `content://` URIs and read through `ContentResolver`; do not assume a filesystem path. The receiver collects both `EXTRA_STREAM` and `ClipData` URIs, removes duplicates, and tolerates providers that do not expose display name or size metadata. It attempts a persistable read grant only when a sender includes a read grant; providers that do not support persistence continue to use the activity grant. `ACTION_OPEN_DOCUMENT` selects outgoing items.

The send screen hands selected URIs to `Intent.createChooser()` using `ACTION_SEND`/`ACTION_SEND_MULTIPLE`, the provider MIME type, `EXTRA_STREAM`, `ClipData`, and `FLAG_GRANT_READ_URI_PERMISSION`. This lets Android surface Quick Share as a system destination where the installed OS provides it. The system Quick Share component owns nearby discovery, the transfer protocol, user consent and progress; NearDrop neither calls a private Quick Share API nor impersonates Quick Share. On the receive side, NearDrop remains a regular Sharesheet target for other apps that explicitly share files into it. This is distinct from Quick Share receiving a peer transfer into Android's own Downloads flow.

For edge-to-edge windows the activity draws transparent system bars, sets light system-bar icons for its dark appearance, and the screens apply status-bar, display-cutout and navigation-bar insets. The home sheet enters with a short spring-and-fade motion; screen navigation and file-row placement animate when Android animations are enabled. The entrance transitions are disabled when the system animator scale is disabled.

The app requests no Bluetooth/location permissions until a discovery implementation exists. When BLE is added, runtime permissions must be version-gated (`BLUETOOTH_SCAN`/`BLUETOOTH_ADVERTISE` on modern Android) and justified; no broad storage permission is needed for SAF. A foreground service is not started by the scaffold. Production transfer service must declare an appropriate foreground service type and notification according to the target SDK in use.

The build uses Android Gradle Plugin 9.2.1 with Gradle 9.4.1, built-in Kotlin and Compose compiler plugin 2.2.10. The current workstation uses Android SDK API 36 and Build Tools 36.0.0 under the mounted `vaibes-tools/android-sdk/vaibes-android-sdk`, with JDK 17. `android/local.properties` records the local SDK path and is ignored by Git. A debug build of the redesigned UI and Sharesheet receiver completed successfully on 2026-11-09. The Gradle build does not yet invoke Cargo or package `libneardrop_ffi.so`; JNI is a prepared boundary, not a live Kotlin-to-Rust call in this APK.
